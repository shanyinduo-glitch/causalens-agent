# 当前版本演示指南

适用入口：对话探索工作台。旧版截图与周报用于说明开发过程，不用于定位当前按钮。

## 1. 首次提问

按 [README](../README.md#快速开始) 启动网页。上传 `data/student_performance.csv`，在左侧补充背景，例如“这是学生成绩示例，只进行探索，未提供外生性依据”。确认模型访问范围。

在「2. 建立本数据知识库」点击「建立／更新本地知识库」。页面应显示片段数与检索模式；若降级为词项检索，展示实际状态即可。

在「3. 现在问助手」的「你的问题」输入：

> 请检查 study_hours 和 score 的缺失情况与描述统计，绘制两者的散点图。只描述统计关联，不执行因果估计；不要替换变量。

点击「发送并开始探索」。展示图表和计算事实，再展开「计划、工具执行与引用依据」。不要预先承诺模型一定调用固定的工具序列。

## 2. 追问与组间比较

选择「只解读上一轮结果（不执行工具）」：

> 这些结果说明了什么？为什么不能据此判断因果关系？请不要重新计算。

再切换「继续探索／提出新分析」：

> 请比较不同 major 的 score，并画各专业平均分柱状图。说明各组样本量和结论限制，不进行因果估计。

验收：前一轮只解释已有结果，后一轮可以产生新工具结果；输入框位于结果历史上方。

## 3. 研究设计与审批

使用 `data/synthetic_causal_data.csv` 单独演示二元处理路径。新数据拥有独立会话。

在顶部进入「研究设计与人工配置」，选择快速引导或专业契约。参考 `examples/causal_contract.example.json` 核对实际字段：处理变量 `ad_exposure`、结果变量 `retention_score`，控制变量 `age`、`log_income`、`historical_activity`、`channel_score`。补充目标人群、每行代表的单位和结果时间窗，明确这是模拟数据。

先展示方法适配、研究配置和诊断，再人工批准。批准前不执行估计；配置不完整时应解释缺什么；结果应包含假设与局限。不要将学生数据强行套用广告曝光字段。

黄金案例仅在本机持有对应私有 CSV 时展示：使用 `t_diff`、`y_ret`、`date`，比较 LP 与论文连续处理 DML 的目标；连续 DML 当前只是方法比较候选，不在该案例中实际运行。

## 4. 报告与失败处理

下载用户简报、技术记录和会话 JSON。简报用于阅读，技术记录用于复核工具输出与参数。

如果工具成功但报告模型超时，应保留图表和事实摘要，并标明 AI 解读未完成。此时使用「只解读上一轮结果」，无需重复计算，也不能宣称整轮模型调用成功。

建议讲解顺序：真实问题与工具输出 → 不重新计算的追问 → 知识来源与方法候选 → 审批和技术记录。演示不要求统计检验显著，重点是问题、证据、工具、人工决策和结果能够相互核对。
